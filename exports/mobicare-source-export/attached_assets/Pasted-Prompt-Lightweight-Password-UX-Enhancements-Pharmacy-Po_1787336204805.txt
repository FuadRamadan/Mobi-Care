Prompt: Lightweight Password UX Enhancements (Pharmacy Portal)

Add the following to the pharmacy password-change and login experience in MobiCare. Keep it frontend-heavy and minimal on backend calls — these are UX/polish features, not core security logic.

1. Self-contained forced-change screen

The "Set New Password" screen (shown when must_change_password is true or password has expired) should only call the backend once, on submit.
Do not fetch dashboard data, pharmacy profile, or any other resource on this screen — load nothing until the password is successfully changed and a full session token is issued.

2. Client-side password validation (no server round-trips)

Fetch the password policy (min_length, require_uppercase, require_number, require_symbol) once when the screen loads, and cache it in frontend state/session storage for that session.
Validate the password against the policy entirely client-side as the user types, with debounced input (e.g., 200–300ms) to avoid re-validating on every keystroke.
Show live checkmarks per rule (e.g., "✓ 8+ characters," "✓ contains a number," "✓ contains uppercase") that update in real time.
Only hit the backend once, on final submit, for the actual password change + policy re-validation (server-side check is still required for security — client-side is UX only, not the source of truth).

3. Password strength meter

Add a simple visual strength bar (weak / medium / strong) below the new-password field, using a lightweight scoring approach — either the zxcvbn library or a basic custom scorer (length + character variety + common-pattern check) if you want to avoid the extra bundle size.
Update the meter live as the user types, same debounce as above.
Purely visual feedback — does not block submission (the policy checkmarks handle that).

4. Expiry countdown banner

When a pharmacy logs in and their password is within a configurable warning window of expiry (e.g., last 5–7 days, reuse max_password_age_days from the policy to calculate this), show a small dismissible banner: "Your password expires in X days — update it now."
Banner should be dismissible per session (don't re-show after dismissal until next login), and include a direct link/button to the password-change screen.
No polling — calculate expiry from password_last_changed_at and the policy at login time, pass it down with the login response.

Constraints

No new backend endpoints needed for items 2–4 (reuse existing policy and login response payloads).
Keep bundle size minimal — if using zxcvbn, consider zxcvbn lite/lazy-loaded only on the password-change screen, not globally.
